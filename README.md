# Spooky Grove

An illustrated scene editor hosted privately on OpenAI Sites.

## Editor
- Reopens the last in-progress creation. Only an account or guest with no existing draft starts empty in a randomly chosen world, which is saved immediately and stays stable on refresh. Haze remains available, with a lavender sky, subtle mist, and a textured ground horizon. Sign-in drafts take precedence, and existing creations keep their original world. Tapping an oddity thumbnail adds it directly in the center with a brief confirmation. Canvas taps select placed items for editing. Light mode uses the literal first-version solid background, #faf3f3, with no pattern, gradient, or texture. Modern control styling remains. The interface defaults to dark mode and remembers the light/dark choice on the current device.
- An All filter opens the themed category dropdown by default. Eight categories and their oddities are alphabetized: Bones, Creatures, Fungi, Magic, Nature, Plants, Sky, and Structures. The catalogue has three columns with vertical scrolling on desktop and two rows with horizontal scrolling on mobile, including search results and heart-filtered favorites. The picker contains 140 items. The retired cat ID and artwork remain renderable for existing creations. The original Cat is now labeled Black Cat Sitting. Penguin uses natural feather texture without mushrooms. Search includes category vocabulary, normalized singular/plural terms, and curated related words, so Bones finds the entire category and birds, fungi, skulls, weather, and other related terms find matching oddities.
- Place items, move them with a pointer or touch, resize them up to 300% of canvas width and rotate them simultaneously with any corner handle, flip them horizontally or vertically, copy them with their properties intact, remove them, and use 80-step Undo and Redo beside the canvas. Each drag, resize, or rotation gesture is one step, and a new edit discards the redo branch. Select objects directly on the canvas. Selected objects have 48-pixel touch targets for direct size and rotation gestures. On a focused corner, up and down resize, left and right rotate, and Shift enables finer steps. The pointer gesture keeps the object center fixed, unwraps angle changes, ignores additional pointers, and protects against abrupt rotation when crossing the center. Copy creates a visibly offset top-layer instance with the same size, flips, and rotation, selects it, and is one undoable step. Blank touch gestures scroll the page, while gestures beginning on the selected illustration drag it.
- Twenty-seven scene choices, plus Blank canvas. All world art is free of sun and moon discs so celestial objects can be placed independently. Void is a plain near-black plum field. Space and underwater have no ground.
- Moons, galaxies, eclipses, a satellite, shooting stars, weather, and a tornado stamp. Rain and snow have stronger visible strokes and flakes. Choosing weather replaces the previous effect. Legacy saved combinations remain intact until a weather choice is changed. Sky objects are selected as items, with only weather controls at the bottom.
- Eight three-color swatch palettes include Original and a full-scene Black And White treatment. Complete color transforms affect every illustrated world, and all render consumers share the same canvas routine. Void remains a uniform near-black plum field. Oddities is always expanded. Three compact controls, Background, Weather, and Palette, sit directly above the canvas. Weather and Palette open themed panels. Each control shows its selected value, with compact ellipsis for long background names. New creations use Normal weather and Original palette. Restored settings retain their saved values.
- Background, category, and Album-sort menus share themed popups with keyboard navigation and preserved scroll position. New oddities stack above older ones in the scene array, screen rendering, PNG export, and saved scenes.
- New and the secondary Randomize button sit together at the bottom. The top-right User Menu contains Light/Dark Mode, History, and Album. Add To Album opens a themed naming prompt before saving. Download combines an icon and label, and Share is an accessible icon button. Undo, Redo, Copy, Flip, and Remove share a compact row below the canvas. The selected oddity name replaces the idle prompt, with insertion-order numbers for duplicates. This order is saved independently of the layer array. No visible manipulation instructions or separate rotation icon remain. Toasts and operation status appear centered without intercepting pointer input. Surface radii match on all four corners, and the User Menu button has a transparent background. Album supports chronological, reverse chronological, alphabetical, and reverse alphabetical sorting across all pages. Each Album or History card has an accessible ellipsis action menu. Album retains Edit, Rename, and Delete, while History retains Edit, Add To Album, and Delete. Clicking an Album or History thumbnail saves the current creation to History before opening it for editing, and a failed save blocks replacement.

## Account persistence
The existing Sites dispatcher provides the authenticated user ID. Built-in ChatGPT sign-in is used. No Google OAuth or app-owned login credentials are used. The private Site access boundary is unchanged. API requests without this identity are rejected.

D1 stores each account’s current draft, scene JSON, Album/History metadata, account-scoped favorite item choices, and transactional naming counters. History names display as Auto Save 1, Auto Save 2, and so on. New and renamed Album names allow up to 15 Unicode characters, with duplicate suffixes included in the limit. Existing longer names remain unchanged. Manual Album names are entered before saving, preserve the user’s capitalization, and receive a numbered suffix when duplicated. Leaving the name empty uses the next Grove number. Name allocation and insertion run in the same D1 transaction. Album titles can be renamed independently of History titles. Creation timestamps remain separate metadata, display without seconds at the bottom of equal-height cards, and titles reserve two lines. Counter increments and record inserts are a single D1 transaction, so simultaneous saves cannot reuse a number, failed saves do not consume one, and deletion never resets the sequence. Favorites is a filter, not a ninth category. R2 stores thumbnails. Every list, read, thumbnail, and update is filtered by the authenticated owner. The frontend never supplies the owner ID. Mutating requests require a matching Origin and an application header.

Every confirmed New, Randomize, or Edit first saves and verifies the existing scene in History. Editing interactions are locked during this operation. If saving fails, the current scene remains unchanged. Album is saved manually, and History records can also appear in Album. Creations retain editable scene data, not just pictures. Individual saved records can be permanently deleted only after a themed confirmation names the target and affected collections. Server-side deletion checks owner, collection membership, confirmation, and the current title. Removing a record deletes it from both Album and History when present in both, and removes its thumbnail. A thumbnail cleanup failure is reported without misrepresenting the outcome.

The editor supports anonymous play when hosted with public access, but this deployment remains private. Save, Album, History, synced Favorites, New, and Randomize prompt anonymous visitors to sign in. Download and Share work without an app account. A pending login draft stays in tab-scoped session storage and is restored before editing is enabled after returning from sign-in. Drafts are not cloud saves. Loading operations show a spinner and a specific status, including loading favorite oddities, saving to Album, loading worlds, and editing saved creations.

Blank is a flat, subtly tinted near-white world. Void remains near-black. Light-mode oddity tiles share a flat surface, and the title has no shadow. Scrollable panels use persistent themed overflow tracks with keyboard and pointer controls, including on systems that hide native scrollbars. No track appears without overflow. Interface labels and catalogue names use Title Case, while user-entered creation names remain unchanged.

Current creations autosave to an owner-scoped D1 row after edits. Draft writes carry the opaque account scope returned by the server, so a changed sign-in cannot write the previous account’s scene into another account. A pending device backup protects edits during network interruption and is read only after the account is identified. Requests are serialized, retried edits are idempotent, and simultaneous first visits cannot replace an existing draft with a new random world. Guest drafts stay on the current device. A failure to read a cloud draft never silently starts a new random world. Album and History remain separate from the working draft.

## Source and build
- `public/` contains the client and bundled original artwork.
- `worker/index.js` contains the authenticated API and static asset fallback.
- `db/schema.ts` and the immutable `drizzle/` migrations define storage.
- `npm run build` produces Cloudflare Worker output and client assets.

A server is required for Album and History. The artwork and editor remain portable, but a future itch.io edition needs an explicit persistence plan rather than pretending account saves are device-local.
